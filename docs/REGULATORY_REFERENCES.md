# Regulatory & industry context — Change Control

> Portfolio prototype only. Not validated software.

## Why regulators care about change control

When a computerized system supports CGMP, device QMS, or clinical decisions, **uncontrolled change** can break the link between validation/assurance evidence and the system in use. Expectations appear across:

| Source | Relevance |
|--------|-----------|
| **21 CFR Part 11** | Controls for electronic records; system validation; audit trails; limited access ([eCFR Part 11](https://www.ecfr.gov/current/title-21/chapter-I/subchapter-A/part-11/)) |
| **FDA Part 11 Scope & Application** | Risk-based thinking on validation and audit trails |
| **21 CFR Part 211** | CGMP — equipment, records, production systems |
| **21 CFR Part 820 / QMSR** | Device quality system — document control, production/process controls, software in QMS |
| **FDA CSA guidance** | Risk-based assurance for production/QMS software after changes and during lifecycle |
| **EU GMP Annex 11** | Computerised systems — change control as part of system lifecycle |
| **ISPE GAMP 5** | Industry framework: change management for GxP systems (not law) |

## Themes this prototype illustrates

1. **Impact assessment** before implementation  
2. **Approval** before execution  
3. **Evidence** of what changed  
4. **Verification** that the system still meets intended use  
5. **Traceable history** of decisions (audit-oriented log)

## Non-claims

No electronic signatures under Part 11 Subpart C, no formal IQ/OQ/PQ protocols, no production data, no regulatory submissions.

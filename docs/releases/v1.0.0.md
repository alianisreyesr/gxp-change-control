# GxP Change Control v1.0.0

This is the first public portfolio release of **GxP Change Control Tracker**, a full-stack demonstration of controlled software-change workflows.

> **Portfolio boundary:** All records and scenarios are synthetic. This repository is not validated software and must not be used to approve real changes, support product release, make regulated quality decisions, or claim compliance.

## Highlights

- Change requests with system, type, priority, requester, business justification, and target date
- Structured impact assessment for validated state, Part 11 controls, data integrity, training, and SOPs
- Explicit `approve`, `reject`, and `request_info` decisions
- Controlled progression through implementation, verification, and closure
- Attributable application-level activity records with server-generated UTC timestamps
- React 19 reviewer interface with Ajv schema validation
- FastAPI and Pydantic v2 API with OpenAPI and exported JSON Schemas
- IANA time-zone handling, UTC normalization, DST fold detection, and nonexistent-time rejection
- SQLite persistence with synthetic seed data
- Docker API profile

## Verification baseline

The release commit is published only after the same SHA has completed successfully in:

- 68 pytest tests with coverage generation
- TypeScript type checking and Vite production build
- Bandit SAST
- `pip-audit`
- `npm audit --audit-level=high`
- Docker API image build
- CodeQL for Python and JavaScript/TypeScript
- Sonar workflow execution or an explicit credential-aware skip

## Important limitations

This version does **not** provide:

- authentication, role-based authorization, or segregation of duties;
- electronic signatures, re-authentication, or signature meaning;
- independently protected or immutable audit storage;
- governed implementation-task and verification-evidence records;
- production database migrations, backup/recovery, retention, monitoring, or high availability;
- formal validation or assurance for a regulated intended use.
